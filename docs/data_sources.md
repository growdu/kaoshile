# 数据源策略与白名单

> 版本：v0.1（2026-10-13）
> 对应文档：[requirements.md](./requirements.md)、[design.md](./design.md)、[seed_exams.md](./seed_exams.md)

---

## 1. 为什么需要单独这份文档

考试通知软件的**核心可靠性**建立在「考试时间数据是准的」之上。本文档回答三个问题：

1. 数据**从哪儿来**？（白名单）
2. 数据**怎么录进来**？（录入与复核流程）
3. 数据**会不会过期**？（时效与变更检测）

> 原则：**采集自动化永远弱于「人工 + 半自动辅助」**——尤其在国内公开考试没有统一 API、且 ToS 与反爬各异的现实下。本项目 v1 不做主动抓取。

---

## 2. 策略总览

| 阶段 | 策略 | 自动化程度 | 合规风险 |
| --- | --- | --- | --- |
| **v1** | 人工录入 + 半自动解析助手 | 低 | 极低 |
| **v1.1** | RSS / 邮件订阅聚合 + 用户自助申报 | 中 | 低 |
| **v2** | 受限抓取（仅 robots.txt 允许的白名单源）+ 社区协作 | 中高 | 中（需逐源评估） |

v1 任何超出「人工 + 解析助手」范围的自动化动作都必须先更新本文档并经评审。

### 3.4 明确**不收录**的类别（写进 non-goals）

- **商业认证**：阿里云 / 华为云 / 腾讯云 / AWS / Azure / Oracle / Cisco / Red Hat 等厂商认证——它们有自己的平台、节奏完全不同，应单独产品化；
- **企业内训 / 厂家组织考试**：不属于公开考试；
- **国际考试（境外考点主导）**：IELTS / TOEFL / GRE / GMAT 等考点信息极分散，本产品仅按「考点」维度轻量标注，不抓官方时间表；
- **学历类（高考 / 研考）的全国性大考**：单独专题产品更合适，本项目 v1 仅做提醒不替代官方服务。

## 4. 录入与复核流程

### 4.1 流程图

```
管理员 → 浏览权威源公告
   ↓
复制公告正文 → 粘贴到「解析助手」
   ↓
解析助手按规则提取关键字段（见 §4.3）
   ↓
管理员核对 + 修正 → 提交入库
   ↓
入库考试记录带 source_url + last_verified_at
   ↓
每日 job 检查 last_verified_at > 30 天 → 管理员后台红点
```

### 4.2 录入字段（与 `requirements.md §6.1` 一致，附加）

| 字段 | 说明 |
| --- | --- |
| `source_url` | 本条数据来源公告 URL（必填） |
| `source_hash` | 公告正文 SHA256（用于变更检测） |
| `last_verified_at` | 上次人工复核时间 |
| `verifier` | 复核人（管理员账号） |

### 4.3 解析助手规则（v1 启发式）

按以下顺序尝试提取，提取失败回退到人工填写：

1. **时间模式**：正则匹配 `YYYY年M月D日`、`YYYY-MM-DD`、`M月D日-M月D日`；
2. **名称模式**：包含「考试 / 资格 / 职称 / 注册」等关键词的标题；
3. **官方源启发**：若 URL 含 `cpta.com.cn`，按中国人事考试网模板匹配字段；
4. **人工兜底**：任何字段解析失败均不阻塞提交，只高亮提示。

解析助手**只辅助**，**不自动提交**。提交必须有管理员显式确认。

### 4.4 复核规则

- 录入后 **7 天**内复核：管理员需主动点击「确认无误」；
- **30 天**未复核：管理员后台红色告警 + 在考试详情页显示「数据可能过期」徽标；
- **90 天**未复核：考试自动转入 `draft` 状态，停止被新用户订阅。

---

## 5. 变更检测（v1 基础版）

每次管理员点击「复核」时，重新抓取（仅 1 次请求）`source_url`，计算正文 hash：

- **相同**：更新 `last_verified_at`；
- **不同**：管理员后台黄色告警，提示「该公告已更新，请核对」，列出 diff（按行级 SHA256 比对）。

> v1 不主动抓取，仅在管理员复核时按需请求。

## 6. 数据质量指标

> 用于管理员后台的「数据健康看板」（v1.1 落地）。

| 指标 | 健康阈值 |
| --- | --- |
| 考试目录总数 | ≥ 50 类（首屏灌入） |
| 平均 `last_verified_at` 时间 | ≤ 14 天 |
| 90 天未复核占比 | ≤ 5% |
| source_url 缺失占比 | 0% |
| 用户投诉「时间不准」工单 | ≤ 2 / 月 |

---

## 7. 合规与边界

1. **不爬取**：v1 不抓任何页面；解析助手只接受管理员**手动粘贴**的文本；
2. **ToS 友好**：所有复核请求都带 `User-Agent: Kaoshile-Verifier/0.1 (+contact)`，频率 ≤ 1 次 / 公告 / 7 天；
3. **不替代官方**：所有考试详情页与通知中都必须显示**官方源链接**，用户必须回官方完成报名；
4. **个人信息**：用户只留邮箱 + 手机，不采集身份证号 / 姓名；
5. **数据存储**：考试目录数据非个人数据，可入日志做改进；但公告原文不留库（仅留 hash）。

## 8. 演进路径

### 8.1 v1.1：RSS / 邮件订阅聚合

- 对支持 RSS / Atom 的源（中国人事考试网部分栏目、教育部考试中心）做轻量聚合；
- 管理员订阅 → 推回系统 → 自动解析 → **仍需管理员人工确认**入库；
- 失败告警：feed 拉取失败 → 管理员后台红点。

### 8.2 v2：受限抓取

- 仅在以下条件**全部满足**时开启对某源的抓取：
  1. `robots.txt` 允许；
  2. 频率限制 ≤ 1 次 / 6 小时；
  3. 抓取结果必须人工审核后才入库；
  4. 失败 / 变更时停止抓取并报警；
- 抓取脚本独立部署，与 Web 服务隔离；
- 任何抓取动作都记录到审计日志（who / when / which source / what diff）。

### 8.3 v2.x：用户自助申报

- 用户提交一条考试信息（含官方源链接）；
- 管理员后台一键审核；
- 引入贡献者信誉系统：多次通过 = 信誉提升，新提交自动审核比例提高。
