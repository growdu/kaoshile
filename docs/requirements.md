# 需求文档 — 考试通知软件

> 版本：v0.1（2026-10-13）
> 范围：v1.0 MVP

---

## 1. 项目背景

### 1.1 现状与痛点

- 各类资格考试（建造师、会计师、教师资格、研究生、软考、医疗、公务员等）报名时间分散且周期短，错过报名 / 缴费 / 打印准考证窗口的比例极高；
- 官方公告多发布在不易持续关注的网页上，普通用户难以聚合；
- 即便记住了日期，临到头仍可能因忙碌忘记；
- 短信 / 邮件提醒是低成本且覆盖率最高的渠道，但目前缺少一个**轻量、开箱即用、用户自助选择考试并订阅提醒**的产品。

### 1.2 项目目标

做一个**用户自助订阅考试提醒**的轻量 Web 服务：

1. 提供一份**考试目录**，包含每场考试的关键时间节点（报名开始 / 报名截止 / 缴费截止 / 准考证打印 / 考试日）；
2. 用户在前端选择要订阅的考试，留下邮箱 + 手机号；
3. 后台在每个关键节点的**指定提前量**（如考前 7 天 / 3 天 / 当天）自动发送邮件和短信提醒；
4. 用户可随时查询订阅状态、退订、修改联系方式；
5. 提供管理后台录入与维护考试数据。

### 1.3 非目标（v1.0 不做）

- 报名 / 缴费 / 准考证打印的**实际代办**（本服务只做提醒，不代操作）；
- 公告原文爬取（v1 由管理员手工录入，v2 再考虑爬虫）；
- 微信 / 钉钉 / App Push 通知（仅邮件 + 短信）；
- 多语言（v1 仅简体中文）；
- 移动端原生 App（响应式 Web 即可）；
- 付费 / 会员体系。

## 2. 用户角色

| 角色 | 描述 | 主要诉求 |
| --- | --- | --- |
| **访客** | 未订阅的用户 | 浏览考试目录、了解时间节点 |
| **订阅用户** | 已留下联系方式的用户 | 接收考试提醒、查看 / 修改自己的订阅、退订 |
| **管理员** | 维护考试目录与系统配置的角色 | 录入 / 修改考试、查看发送日志、处理异常 |

> 简化处理：v1 不做完整的账号体系，订阅用户通过**邮箱 + 一次性令牌（token）** 即可访问自己的订阅；管理员通过单独的登录入口。

---

## 3. 业务流程（核心场景）

### 3.1 主流程：订阅考试

```
[访客]
  ↓ 打开首页 / 考试目录
  ↓ 选择某场考试
  ↓ 进入「订阅」页
  ↓ 填写邮箱 + 手机号 + 期望的提醒提前量
  ↓ 点击「订阅」
[系统]
  ↓ 入库订阅记录（status=pending）
  ↓ 发送「确认邮件 / 短信」（含确认链接）
  ↓ 等待用户点击确认
  ↓ 点击确认链接 → status=active
  ↓ 按时间调度，发送通知
[订阅用户]
  ↓ 在节点前 7d / 3d / 1d / 当天收到邮件 + 短信
  ↓ 可随时点邮件里的「退订」或访问「我的订阅」页
```

### 3.2 通知触发节点（每场考试共 5 类）

| 节点 | 默认提前量 | 备注 |
| --- | --- | --- |
| 报名开始 | 开始时刻前 1 天 | 提醒：今日可报名 |
| 报名截止 | 截止前 3 天、1 天、当天 9:00 | 三次提醒 |
| 缴费截止 | 截止前 3 天、1 天、当天 9:00 | 三次提醒 |
| 准考证打印开始 | 开始前 1 天 | 提醒：明日起可打印 |
| 考试日 | 考前 7 天、3 天、1 天、当天 7:00 | 四次提醒 |

> 提前量可由订阅用户在订阅时按考试维度选择预设档位（保守 / 标准 / 强烈），详见 §4.3。

### 3.3 退订流程

- 邮件 / 短信内含**退订链接**（带 token），点击即可将订阅标记为 `cancelled`，不再发送任何通知；
- 退订为软删除（保留记录），便于管理员审计。

## 4. 功能性需求

按优先级排序：**P0 = 必须（v1 上线）**；**P1 = 应有**；**P2 = 期望**。

### 4.1 考试目录 [P0]

- **F1.1** 首页展示所有**可订阅**的考试（status=open 且未到报名截止）；
- **F1.2** 考试详情页：展示名称、主办方、报名窗口、缴费窗口、准考证打印窗口、考试日、官方公告链接；
- **F1.3** 支持按「关键字 / 类别 / 时间区间」过滤；
- **F1.4** 状态字段：草稿（draft）、开放订阅（open）、报名截止（registration_closed）、归档（archived）。

### 4.2 订阅管理 [P0]

- **F2.1** 在考试详情页点击「订阅」，进入订阅表单；
- **F2.2** 订阅表单字段：
  - 邮箱（必填，校验格式）
  - 手机号（必填，校验中国大陆 11 位）
  - 提醒档位（单选：保守 / 标准 / 强烈，默认标准）
  - 通知通道勾选（默认邮件 + 短信全开，可单选）
- **F2.3** 提交后立即发送**确认邮件 + 确认短信**（双通道确认，避免无效订阅）；
- **F2.4** 用户点击确认链接 / 回复确认关键字 → `status=active`；
- **F2.5** 「我的订阅」页（通过邮箱 + token 访问）展示所有 active / pending 订阅，可修改联系方式 / 退订。

### 4.3 提醒档位 [P1]

| 档位 | 报名截止 | 缴费截止 | 准考证 | 考试日 |
| --- | --- | --- | --- | --- |
| 保守 | 前 1 天 | 前 1 天 | 前 1 天 | 前 3 天、当天 |
| 标准（默认） | 前 3 天、1 天、当天 | 前 3 天、1 天、当天 | 前 1 天 | 前 7 天、3 天、1 天、当天 |
| 强烈 | 前 7 天、3 天、1 天、当天 | 前 7 天、3 天、1 天、当天 | 前 3 天、1 天 | 前 14 天、7 天、3 天、1 天、当天 |

### 4.4 通知发送 [P0]

- **F4.1** 后台调度器在每场考试每个节点的**发送时刻**触发；
- **F4.2** 通过**阿里云邮件推送 + 阿里云短信**双通道并行发送；
- **F4.3** 模板渲染：节点类型 + 考试名 + 时间 + 用户称呼 + 退订链接；
- **F4.4** 发送结果入库（成功 / 失败 / 失败原因 / 第三方回执 ID）；
- **F4.5** 失败重试：单条通知失败后，指数退避重试最多 3 次；仍失败则标记 `failed` 并通知管理员（v1 通过管理后台红点提示）；
- **F4.6** 发送频率限制：同一订阅同一节点不重复发送（idempotent）。

### 4.5 通知历史 [P1]

- 用户「我的订阅」页可看到**已发送**的通知列表（时间、通道、状态）；
- 管理员后台可见全部发送日志，支持按考试 / 时间 / 状态筛选。

### 4.6 管理员后台 [P0]

- **F6.1** 登录入口（账号 + 密码）；
- **F6.2** 考试 CRUD：录入字段见 §6.1；
- **F6.3** 订阅列表查询（按考试 / 状态）；
- **F6.4** 发送日志查询；
- **F6.5** 模板编辑（简单的字符串替换，不做可视化拖拽）。

### 4.7 退订与合规 [P0]

- **F7.1** 所有通知正文末尾必须包含**退订链接**；
- **F7.2** 用户点退订链接后立即生效，无需登录；
- **F7.3** 退订后 7 天内彻底删除 PII（邮箱、手机号），保留订阅主记录用于审计（id、节点哈希、状态）。

## 5. 非功能性需求

### 5.1 可用性

- **NFR-U1** 服务可用率目标 ≥ 99%（按月计算）；
- **NFR-U2** 单实例故障恢复时间 ≤ 5 分钟。

### 5.2 性能

- **NFR-P1** 订阅提交到确认邮件发送的端到端延迟 ≤ 5 秒（P95）；
- **NFR-P2** 单实例调度器每秒可处理 ≥ 50 条通知触发的扇出；
- **NFR-P3** 考试目录页首屏加载 ≤ 2 秒（P95，4G 网络）。

### 5.3 安全

- **NFR-S1** 邮箱 / 手机号在数据库中**不加密**（业务需要按邮箱查询），但**传输层 TLS**，且管理员查询需登录；
- **NFR-S2** 退订 / 订阅管理 token 使用 HMAC-SHA256 签名，URL 中只暴露 token 后 8 位 + 签名；
- **NFR-S3** 所有管理后台接口强制鉴权；
- **NFR-S4** 阿里云 AccessKey 通过**环境变量**注入，禁止入库。

### 5.4 可观测

- **NFR-O1** 所有外部调用（邮件 / 短信 API）记录结构化日志（时间、订阅 ID、通道、结果、回执 ID）；
- **NFR-O2** 关键操作（订阅 / 退订 / 发送失败）落审计日志；
- **NFR-O3** 健康检查端点 `/healthz` 与就绪探针 `/readyz`。

### 5.5 可扩展性

- **NFR-E1** 通知通道抽象为接口，新增微信 / 钉钉通道不改动业务代码；
- **NFR-E2** 调度器与 Web 服务同进程起步，但代码上解耦，可拆为独立 Worker。

### 5.6 可测试性

- **NFR-T1** 任何业务模块必须有对应单元测试；
- **NFR-T2** 关键流程（订阅 / 通知发送 / 退订）必须有集成测试覆盖 happy path + 主要失败路径；
- **NFR-T3** 外部通道（邮件 / 短信）在测试中必须可被 Mock 替换。

## 7. 约束与假设

- **C1** 阿里云账户已开通 DirectMail 与 SMS 服务，且完成签名 / 模板报备；
- **C2** 短信签名与模板必须事先在阿里云控制台审核通过（合规要求）；
- **C3** 单实例调度器假定进程内调度可靠；如部署多实例，需引入 Redis 锁（v1.1 考虑）；
- **C4** 时间统一使用 **Asia/Shanghai**（UTC+8）；
- **C5** 假设考试目录数据由管理员手工维护，v1 不爬取。

## 8. 验收标准（DoR / Definition1 Done）

满足以下全部条件视为 v1 完成：

1. ✅ 全部 P0 / P1 功能项实现并通过测试；
2. ✅ 单次 commit 配套单元 + 集成测试通过（遵循开发节奏偏好）；
3. ✅ 在测试环境下，完整跑通「订阅 → 确认 → 节点到达 → 收到通知 → 退订」主链路；
4. ✅ 阿里云两个通道均能成功发送一封真实邮件与一条真实短信（带脱敏收件人）；
5. ✅ 关键失败路径（邮件 API 失败 / 短信 API 失败）能正确重试并标记失败；
6. ✅ README.md / 设计文档 / 实现方案与代码一致；
7. ✅ 提交一组 demo 数据（≥ 3 场考试、≥ 5 条订阅）用于验收。
